# Pylines: командный профиль

Этот reference объединяет относящиеся к общему стилю разработки правила исходного скилла.
Разделы специализированной инфраструктуры сокращены под область этого скилла.
Применяй нужный раздел по задаче;
архитектурные правила и рабочий процесс находятся в `../SKILL.md`.

- Прочитаны `SKILL.md` и все пять references: `code-style.md`, `solid.md`, `rest.md`,
  `tests.md`, `stack.md`.
- Исходный скилл ссылается на [community-of-python/pylines](https://github.com/community-of-python/pylines).
  Эта адаптация основана на корпоративной копии, а не на независимо проверенной текущей версии upstream.

Ниже — командные соглашения, а не универсальные требования языка Python. Они дополнены
правилами DI, читаемых сценариев и надёжного выполнения. При переносе сознательно уточнены:

| Исходная формулировка | Как применять в этом скилле |
| --- | --- |
| `Final` на все переменные | На привязки без переназначения; не на параметры, счётчики и заведомо изменяемое состояние. |
| `@final` на все классы | На конкретные классы без точки расширения; не на Protocol, TypedDict и намеренно расширяемые классы. |
| Имена минимум 8 символов | Для новых собственных переменных и функций; специальные и внешние имена сохраняются. |
| Retry для всего вне RAM | Анализировать отказ каждого I/O; повторять временные ошибки только при безопасной семантике повтора. |
| Всегда LBYL | Для локальных проверок; в конкурентном I/O предварительная проверка не устраняет гонку. |
| Всегда параллельные тесты | При изолированных ресурсах и поддержке xdist; иначе последовательный запуск с указанием причины. |
| Только генерируемые тестовые данные | Генерация для вариативности; фиксированные значения для регрессий, границ и понятных ожиданий. |
| `unsafe-fixes = true` | Небезопасные автоисправления не включать постоянно; каждое изменение должно быть проверяемым. |
| Нет вложенности URL | Запрет цепочек вложенных ресурсов; адрес отдельного ресурса с идентификатором допустим, как в исходных примерах. |

## Стиль, типы и изменяемость

- Базовый профиль: Ruff, длина строки 120, строгий mypy, uv.
- Аннотируй весь собственный публичный и внутренний контракт. Для локальных скаляров
  используй вывод типов: `retry_limit: typing.Final = 3`.
- `typing.Final` запрещает переназначение привязки при статической проверке; содержимое
  списка или словаря всё ещё может изменяться. Для действительно неизменяемых данных
  выбирай `tuple`, `frozenset` и подходящие вложенные типы.
- `types.MappingProxyType` даёт read-only представление словаря, но не глубокую копию
  и не защиту от изменения исходного словаря через другую ссылку.
- `frozen=True` фиксирует поля dataclass, но не делает клиент, хранящийся в поле, immutable.
  Для объекта с законным изменяемым состоянием используй обычный класс или подходящую dataclass.
- `slots=True` и `kw_only=True` — предпочтительный шаблон собственных компонентов;
  сначала учитывай требования фреймворка, наследования и сериализации.
- Сужай типы по реальным инвариантам. Не вводи Enum, NewType и обёртку вокруг каждого
  `str`, если они ничего не проверяют и не предотвращают путаницу.
- Не скрывай ошибки типизации массовыми `Any`, `cast`, `# type: ignore` и глобальным
  отключением проверок. Для нетипизированной сторонней библиотеки локализуй границу.
- Type checker проверяет структурную совместимость, но не доказывает поведенческий LSP:
  предпосылки, эффекты и допустимые ошибки проверяются контрактами и тестами.
- Не создавай глубокие иерархии; маленький Protocol описывает потребность вызывающей стороны.
  Не добавляй `@runtime_checkable`, если runtime-проверки интерфейса не нужны.
- Для regex, обрабатывающего недоверенный ввод, оцени сложность и ограничения длины.
  Не отправляй корпоративные шаблоны и данные внешним проверяющим сервисам.

## Tooling для нового проекта или запрошенной настройки

Не заменяй существующий конфиг целиком. Сначала проверь используемые версии Python и
инструментов; адаптируй правила к ним. Базовые команды при выборе uv:

```bash
uv add --dev ruff mypy community-of-python-flake8-plugin flake8-pyproject auto-typing-final
uv run ruff check .
uv run ruff format --check .
uv run mypy .
uv run flake8 .
```

`community-of-python-flake8-plugin` исполняется через Flake8; `external = ["COP"]`
не заставляет Ruff выполнять сторонний плагин. `auto-typing-final` применяй к
подходящим привязкам с просмотром diff и последующим type check.

Адаптированная основа `pyproject.toml`:

```toml
[tool.ruff]
line-length = 120

[tool.ruff.format]
docstring-code-format = true

[tool.ruff.lint]
select = ["ALL"]
external = ["COP"]
ignore = ["EM", "FBT", "TRY003", "D1", "D203", "D213", "G004", "FA", "COM812", "ISC001"]

[tool.ruff.lint.isort]
no-lines-before = ["standard-library", "local-folder"]
lines-after-imports = 2

[tool.ruff.lint.extend-per-file-ignores]
"tests/**/*.py" = ["S101", "S311"]

[tool.mypy]
strict = true

[tool.flake8]
select = ["COP"]
exclude = [".venv", ".cache"]

[tool.coverage.report]
exclude_also = ["if typing.TYPE_CHECKING:"]
```

Обоснования исключений: EM/TRY003 не требуют отдельной переменной для сообщения ошибки;
FBT разрешает осмысленные boolean-аргументы; D1/D203/D213 не навязывают очевидные docstring;
COM812/ISC001 исключены для совместимости с форматтером. `FA` не заменяет проверку
минимальной версии Python. `S101` и `S311` ослаблены только для тестов.

Укажи `target-version`, `requires-python`, локальные пакеты и области проверки по реальному
проекту. Ruff `ALL` меняется с версией: исключения добавляй обоснованно. Не включай
`fix = true` для проверок CI; форматирование и исправления запускай отдельным действием.

## Тестирование

- AAA: подготовка → одно проверяемое действие → проверка наблюдаемого результата.
- Предпочитай интеграционный тест для взаимодействия компонентов, хранения и API.
  Unit-тест подходит для сложного чистого правила и точной воспроизводимой регрессии.
- Используй pytest и `@pytest.mark.parametrize` для набора случаев одного поведения.
- Faker/Polyfactory сокращают подготовку нерелевантных полей. Hypothesis проверяет
  свойства и диапазоны. Schemathesis полезен для проверки API-контрактов, когда это часть задачи.
- Не делай тест зависимым от случайности, текущего времени, порядка запуска или внешнего
  production-сервиса. Контролируй время и генерацию, сохраняй воспроизводимость отказа.
- Используй `uv run pytest -n auto`, если установлен pytest-xdist и каждый тестовый процесс имеет
  изолированные БД/схемы, временные каталоги и порты. Если изоляции нет, запускай
  существующим безопасным способом; внедрение параллельности не включай в любую правку.
- Подменяй инфраструктурную границу или используй тестовый адаптер. Не мокируй каждый
  приватный метод проверяемого сценария.
- Для сценария существенны: корректный итог, ветвления, ранний выход, ошибка этапа
  и отсутствие ложного success — в пределах затронутого поведения.

## REST API

Это профиль для нового или явно пересматриваемого API. Совместимость существующих URL,
клиентов, кодов ответа и схем сохраняй, если изменение контракта не запрошено.

- Основной формат JSON. HTTP/2 или HTTP/3 — целевой транспорт при поддержке окружением;
  это настройка сервера/прокси, а не основание переделывать бизнес-код.
- Ресурс в URL называй существительным, действие выражай HTTP-методом. Для RPC используй глагол.
- Шаблоны: `/rest/{service}/{entities}/`, `/rest/{service}/{entities}/{identifier}/`,
  `/rpc/{service}/{action}/`. Разделитель в сегментах — дефис, в конце — слеш.
- Префиксы: `rest`/`rpc`, `rest-internal`/`rpc-internal`, `rest-public`/`rpc-public`
  по аудитории. Префикс сам по себе не обеспечивает авторизацию.
- Не строй цепочки вложенных ресурсов; связи выражай фильтрами. Выбери единообразное число имён.
- Реализуй только нужные операции; не создавай полный CRUD по шаблону.
- Версионируй только при необходимости; командное предпочтение — версия в `Accept`.
- Новые необязательные поля вводи со значениями по умолчанию там, где это сохраняет контракт.
  Учитывай, что даже добавление поля может затронуть строгого клиента.
- Следуй существующему способу генерации OpenAPI; наличие code-first подхода не заменяет
  проверку фактической схемы и ответов.

## Предпочтения исходного стека

Это зафиксированные предпочтения исходного гайдлайна, не обещание актуальности каждого
пакета и не команда установить всё перечисленное. При выборе новой зависимости проверь
её официальную документацию, поддержку версии Python и пользу для конкретной задачи.
Существующие аналоги сохраняй, если их замена не входит в задачу.

| Область | Предпочтения pylines |
| --- | --- |
| Web | Litestar; FastAPI; Django + django-ninja для MPA/админок |
| Сервер и bootstrap | granian, microbootstrap |
| DI при необходимости контейнера | that-depends, modern-di, dishka |
| ORM и key-value | SQLAlchemy; Redis/Valkey/Dragonfly через async redis-py |
| HTTP | community-of-python/base-client; httpx/niquests для специальных случаев |
| Валидация и конфигурация | pydantic/msgspec, pydantic-settings |
| Retry и circuit breaker | stamina, circuit-breaker-box |
| Логи и трассировка | structlog, MemoryHandler при подходящей политике буферизации, OpenTelemetry |
| Тесты | pytest, pytest-xdist, hypothesis, schemathesis, polyfactory, faker |
| CLI и кеш | typer, cachebox |
| Файлы | pathlib; aiofile при необходимости async API |
| Специальные задачи | pendulum, pyvips, mpire, aiorun, pydantic-ai, fastmcp, selectolax, python-magic/magika |
| Инфраструктура доступа | Keycloak, Apisix, Istio/mTLS по архитектуре окружения |

В исходном списке также указаны `curl_cffi`, PyPy и pyston. Это специальные инструменты,
а не базовый выбор: потребность, совместимость и состояние поддержки проверяются отдельно.
Для криптографически значимой случайности используй `secrets` из стандартной библиотеки.
