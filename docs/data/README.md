## Текущий локальный формат

Одна строка описывает кредит в одном периоде. [Загрузчик](../../src/ec_analysis/schemas/dataset.py) проверяет обязательные поля, уникальность `(id, period)`, наличие обоих периодов у каждого кредита и числовой тип целевой колонки.

| Колонка демонстрационного CSV | Значение |
| --- | --- |
| `id` | Идентификатор синтетического кредита |
| `period` | Метка сравнения `T0` или `T1` |
| `volume` | Условная денежная величина кредита |
| `interest_rate` | Ставка в долях единицы |
| `pd` | Синтетическая вероятность дефолта в долях единицы |
| `lgd` | Синтетическая доля потери при дефолте |
| `ltv` | Синтетическое отношение кредита к стоимости обеспечения |
| `npv` | Искусственная целевая метрика, а не банковский расчёт NPV |

Канонические формулы находятся в [SyntheticFormula](../../src/ec_analysis/data/synthetic.py), воспроизводимая генерация — в [PortfolioGenerator](../../src/ec_analysis/data/generator.py), CLI — [generate_dataset.py](../../scripts/generate_dataset.py). Сценарии: `credit` (исходная формула), `linear`, `threshold`, `saturation`, `u_shaped`, `interaction`, `mixed`, `regime_shift`. Последний специально добавляет скрытый сдвиг −60 на кредит в T1; в остальных зависимость фиксирована (два дополнительных сценария описаны ниже). Рядом с новым CSV сохраняется `.truth.json`: seed, версия и контрольная сумма формулы, SHA-256 CSV, суммы и изменения генерирующих компонентов. Эти компоненты не входят в факторы и не считаются истинными SHAP-вкладами. [Результаты сравнения](../ml/synthetic-comparison-v1.md).

Загрузчик сохраняет числовые и категориальные признаки, допускает пропуски факторов и отклоняет неконечные числовые значения. Цель, `id`, `period`, `as_of_date` исключены из факторов. Для CLI можно явно задать `--features`; без списка используются остальные колонки, и их временную доступность обязан проверить исследователь. Автоматического обнаружения всех утечек нет. При наличии календарных дат проверяется строгий порядок T0 перед T1. Импутация, масштабирование и кодирование обучаются внутри модели только на обучающей части. Экономические диапазоны произвольного CSV пока не проверяются; импорт Release 47 имеет собственные правила.

## Подготовка реальных данных

Пункты 1–5 реализованы для формата Release 47 в пределах [контракта импортёра](release47-import.md) и проверены на открытом образце и искусственных согласованных строках. Исследование распределений, выбросов и доступности признаков во времени на годовой выборке ещё не выполнено. Учёт входов/выходов пока ограничен числом кредитов и суммами остатков долга, а не вкладом в изменение NPV.

1. Зарегистрировать исходные файлы и формат; хранить неизменённые данные в `data/raw/`, исключённом из Git.
2. По словарю преобразовать специальные коды пропусков, проценты, даты и суммы; не угадывать соответствие колонок по похожим именам.
3. Соединить выдачи и ежемесячную историю, проверить ключи и дубликаты. Сохранить отчёт о количестве строк на каждом шаге.
4. Хранить календарную дату наблюдения и дату доступности признака. Отбор `T0`/`T1` делать поверх истории, не удаляя даты.
5. Для первой проверки выделить парную подвыборку; выдачи, погашения и выходы учитывать отдельным составным эффектом в полном портфельном сценарии.
6. Разделить наблюдаемые поля, оценённые параметры и целевую метрику. Перечень допустимых факторов версионировать.

## Версии и качество

Загрузчик сохраняет `manifest.json`: источник, вид образца, URL, имена, контрольные суммы, размеры и время получения. Профилировщик Freddie Mac сохраняет [DataQualityReport](../../src/ec_analysis/data/quality.py): версии формата/импортёра, время проверки, контрольные суммы, число строк/кредитов, пропуски, дефекты, месяцы и состав подвыборки. При экспорте добавляется контрольная сумма подготовленного CSV. Для UCI реализована отдельная версия модельного NPV по [ADR 0006](../architecture/decisions/0006-uci-model-npv.md); банковская формула для ипотеки остаётся неопределённой.

Текущий отчёт проверяет ключи, даты, выбранные числовые поля, пропуски и состав подвыборки. Распределения и потенциальные утечки требуют последующего анализа; `ready_for_pairing` означает только возможность технического объединения. Большие файлы и обученные модели описываются ссылкой и способом получения. Следующие действия — [этапы 1–3 плана](../plan.md).

## Дополнительные проверки генератора

В версии 3 добавлены `correlated` (формула mixed при связи PD = 0.01 + 0.14 × (LTV − 0.4) в обоих периодах) и `no_signal` (постоянная цель 100). Первый сценарий проверяет неоднозначность факторов при корреляции, второй — отказ от выдуманной устойчивости нулевых вкладов. Истинные термы хранятся только в sidecar JSON.

Версия 4 сохраняет прежние формулы и добавляет:

- `full_saturation`: вся цель `20 + 120 × (1 − exp(−volume / 120))` приближается к плато;
- `inverted_u_shaped`: `100 − 400 × (ltv − 0.65)^2 + 100 × interest_rate`, обе стороны максимума наблюдаются;
- `observable_regimes`: `20 + 0.08 × volume + 0.4 × max(volume − 550, 0)`, два видимых диапазона наклона.

Сценарии не передаются модели или классификатору формы. Скрытая временная смена `regime_shift` остаётся отдельным отрицательным контролем; она отличается от видимых режимов одного фактора.

## Профиль произвольного CSV

[DatasetProfiler](../../src/ec_analysis/data/profiling.py) сохраняет `profile.json`: строки и пары, количество строк по периодам, распределение цели, типы/пропуски/уникальность факторов, минимум, максимум, среднее, медиану, стандартное отклонение, квантили и IQR-флаги по T0/T1. Для категорий сохраняются 20 самых частых значений, отмечаются неизвестные в T1 категории и высокая кардинальность. Сильные Pearson/Spearman-связи числовых факторов оцениваются на T0, порог модуля 0.85.

Потенциальная утечка отмечается по названию и почти точной связи фактора с целью. Это предупреждение для исследования, а не автоматическая гарантия доступности информации на дату. IQR-флаги не удаляют строки; экономические границы произвольных признаков не угадываются. Жёсткие проверки загрузчика выполняются до описательного профиля.
