# Метрики прогноза, разложения и устойчивости

Статус: Реализовано

Показатели вычисляются раздельно: малый RMSE не доказывает правильность факторов, точный арифметический баланс не доказывает хорошее приближение реальной метрики, а устойчивость ошибочной модели не делает её верной.

## Прогноз

| Метрика | Определение | Зачем используется |
| --- | --- | --- |
| RMSE | Корень из среднего квадрата ошибки по кредитам T1 | Основной критерий выбора на валидации; сильнее штрафует крупные ошибки |
| Нормированная RMSE | RMSE / std(target T1), с нижней границей масштаба | Ошибка относительно разброса цели; порог прототипа 0.15 |
| MAE | Средний модуль ошибки по кредитам T1 | Ошибка в единицах целевой метрики без квадратичного усиления выбросов |
| Подписанный остаток прогноза | Фактическое изменение суммы T1−T0 минус предсказанное | Показывает величину и направление ошибки портфельного изменения |
| Абсолютный остаток | Модуль подписанного остатка | Удобен для сравнения размера ошибки, но не заменяет знак в балансе |
| Доля остатка | Подписанный остаток / модуль фактического изменения | Сопоставление масштаба ошибки; может быть отрицательной или превышать единицу |

Кандидаты оцениваются на одних валидационных кредитах; победитель проверяется на отдельной тестовой группе. У модели, выбранной по RMSE, портфельный остаток может быть больше, чем у другого кандидата. R² и MAPE в текущий расчёт не включены; MAPE неудобна при малых и знакопеременных целевых значениях.

Для доли используется порог `max(1e-8, 1e-6 * max(abs(initial_value), abs(final_value)))`: ниже него результат `null`. Это вычислительная защита для малого знаменателя. Для принятия объяснения отдельно используется материальность 1% уровня портфельной цели по ADR 0007. Масштаб нормированной RMSE ограничен снизу `1e-8 * max(mean(abs(target T1)), 1)`. Схема — [EvaluationMetrics](../../src/ec_analysis/schemas/state.py), расчёт — [ModelEvaluator](../../src/ec_analysis/engine/evaluation.py).

## Разложение

Объясняется разность прогнозов одной фиксированной модели. Основные факторы и отдельные пары не пересекаются; неизменная база сокращается при равном составе портфеля. Сумма вкладов сверяется с разностью прогнозов, а каждый локальный набор термов — с прогнозом того же кредита и периода.

Численная погрешность хранится в `numerical_error`, локальный максимум — в `max_local_error`. Допуск `1e-6 + 1e-5 * max(abs(prediction), abs(base) + sum(abs(terms)))` учитывает взаимное сокращение термов. Исходное правило ADR 0004 уточнено в [ADR 0007](../architecture/decisions/0007-quality-and-numerical-checks.md). Если проверка не проходит, результат не публикуется как проверенное разложение.

`prediction_remainder` — фактическое изменение минус прогноз; `unexplained_remainder` — фактическое изменение минус сумма вкладов. Их разность равна измеренной численной погрешности. Это позволяет сохранить точный итоговый баланс и не скрывать погрешности TreeSHAP. В верхнем уровне состояния используются эффекты всего портфеля; в сравнении моделей — только валидационные кредиты. Охват всегда указан в `scope`.

## Устойчивость

На каждом повторе обучающие кредиты T0 выбираются с возвращением, весь pipeline переобучается, а вклады рассчитываются для неизменной валидационной подвыборки. Внутренняя случайность модели фиксирована. Такой бутстрэп измеряет чувствительность к обучающим данным, а не ко всем возможным источникам неопределённости.

Для опорного вектора непересекающихся вкладов `v` и вектора повтора `b`:

`similarity = 1 − sum(abs(v − b)) / (sum(abs(v)) + sum(abs(b)))`.

Среднее сходство — `stability_score` в диапазоне [0, 1]: совпадающие векторы дают 1, полностью противоположные — 0. Нулевой опорный вектор не оценивается: статус `no_signal`, score `null`. При неуспешных повторах статус `incomplete`, итоговый score не публикуется; причины сохраняются.

Дополнительные показатели:

- Частота совпадения знака; эффекты меньше 1% суммы модулей опорных вкладов считаются нематериальными, для знака принимаются за ноль.
- Стандартное отклонение и эмпирические квантили 2,5% и 97,5% каждого эффекта. При 20 повторах это предварительный диапазон, не калиброванный доверительный интервал.
- Средняя корреляция рангов модулей материальных эффектов; при недостатке или постоянстве рангов она не определена.

Ориентиры 0.70 и 0.85 настраиваются в [AttributionBootstrap](../../src/ec_analysis/engine/stability.py). Одного score недостаточно для повышения уверенности. Совместные критерии прогноза, остатка, баланса, числа повторов и знаков описаны в [ADR 0007](../architecture/decisions/0007-quality-and-numerical-checks.md). При принятой валидации и тесте допустим `medium`; остальные результаты остаются `low`. Проверка по реальным временным окнам фиксируется отдельными экспериментами.

## Чувствительность к параметрам

Сравниваются все записанные профили одной семьи на тех же валидационных клиентах с опорным профилем, выбранным по валидационной RMSE. Используется то же L1-сходство векторов непересекающихся вкладов; существенность для знаков — 1% суммы модулей опорного вектора. Сохраняются вклады каждого профиля, **минимальное** сходство и **минимальное** совпадение знаков, а не их среднее. Настраиваемые пороги: 0.85 и 0.90.

Все профили должны завершить обучение и атрибуцию; необходимо хотя бы два. Отказы дают `incomplete`, нулевой опорный сигнал — `no_signal`, нарушение порога — `unstable`. Такая модель не получает подтверждения надёжности до выбора победителя. Три профиля не покрывают все возможные настройки. [Расчёт](../../src/ec_analysis/engine/parameter_stability.py) · [ADR 0009](../architecture/decisions/0009-complete-analysis-and-verified-llm.md).

## Глобальная важность

Для выбранной замороженной модели вычисляется исходная RMSE на валидации T1. Один исходный фактор перемешивается между наблюдениями, затем измеряется `RMSE_permuted − RMSE_baseline`. Кодирование категорий выполняет уже обученный pipeline. Значения сохраняются для 10 повторов с фиксированным seed; показываются среднее, стандартное отклонение, минимум и максимум. При большой валидации используется воспроизводимая подвыборка до 2000 строк. Отрицательные значения сохраняются.

Это важность для прогноза в единицах цели, а не подписанный вклад в изменение портфеля: фактор может быть важным для уровня метрики при нулевом изменении. Величины не добавляются в баланс. Корреляция может распределять важность между признаками; перестановка способна создавать редкие сочетания. Валидация уже использована для выбора, поэтому это не новый независимый тест. Разброс повторов не является доверительным интервалом. Метод соответствует определению [permutation importance в scikit-learn](https://scikit-learn.org/stable/modules/generated/sklearn.inspection.permutation_importance.html), реализован с сохранением отдельных повторов в [PermutationImportance](../../src/ec_analysis/engine/importance.py).

## Автоматическая диагностика формы

[ShapeDetector](../../src/ec_analysis/engine/shapes.py) получает только 41 точку условного сечения модели, без названия сценария или формулы. Диапазон — 1–99% обучения T0, остальные факторы зафиксированы на медианах/модах. Значения x нормируются на диапазон [0,1], отклик — на размах.

- Размах ниже `max(1e-8, 0.01 × std(target_train_T0))` даёт `unknown`: численный шум не интерпретируется.
- Нормированная ошибка линейного приближения ≤ 0.025 даёт `linear`.
- Для U/перевёрнутой U нужны внутренний экстремум в 15–85% диапазона, противоположные направления ветвей, не менее 90% согласованных соседних изменений с допуском 0.006 и обе экскурсии ≥15% размаха.
- Для `saturation` нужны почти монотонное сечение, отношение конечного наклона к начальному ≤0.12, размах последних девяти точек ≤0.05 и начальный наклон ≥0.3 в нормированных единицах.
- Для `threshold`/`regime` перебирается разбиение на две прямые: ошибка ≤0.03 и <45% ошибки одной прямой. Монотонные ветви либо одна почти плоская допустимы. Отношение меньшего наклона к большему ≤0.2 при меньшем абсолютном наклоне ≤0.1 даёт порог; иначе — режим.
- Неоднозначная нелинейность остаётся `complex`. Излом и поворот указываются только при соответствующей классификации.

Порог материальности и численные допуски сохраняются в `shapes.json`. Эвристики настраиваются в компоненте; они не устанавливают причинность, статистическую значимость или поведение вне наблюдаемого диапазона. Ошибка формы относительно синтетической истины измеряется **после обучения** и отдельно от ошибки прогноза. Смена выбранной модели по этим итоговым диагностическим результатам не выполняется.

## Время и ограничения

При поиске время кандидата — сумма обучения и валидационного прогноза всех трёх вариантов; подробности каждого сохранены в `tuning_trials`. Для разложения измеряется расчёт вкладов, для бутстрэпа — повторы. Время всего запуска также включает загрузку библиотек и запись файлов. Память пока не измеряется. Все показатели относятся к конкретному окружению; один запуск не является полноценным исследованием производительности.

Числа первого сравнения — в [отчёте моделей](synthetic-comparison-v1.md). Результаты разложения и 20 повторов бутстрэпа сохранены в [отдельном отчёте](attribution-stability-v1.md), без изменения исторических метрик.
