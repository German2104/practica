# Требования к прототипу

Статус: Принято

Источник требований — [исходный кейс](../ec-factor-analysis-case.md). Ниже отделены рабочие уточнения, границы MVP и условия приёмки; исходная постановка сохраняется. После сверки пробелов пользователь поручил полностью продолжить исходное задание и выбрал OpenRouter. [ADR 0009](../architecture/decisions/0009-complete-analysis-and-verified-llm.md) заменяет прежнее исключение LLM. Готовый отчёт по практике сохраняется; текущая форма — в [реестре отчёта](../report/README.md).

## Цель и сценарии

Пользователь риск-функции выбирает метрику и два периода, видит изменение портфельного результата, вклады факторов и взаимодействия, необъяснённый остаток и ограничения. Он может раскрыть отдельный фактор и получить текстовое объяснение, согласованное с расчётами. Рабочая модель одна — GAM с парными эффектами; сравнение семейств относится к исследовательскому сценарию.

Второй сценарий — исследователь сравнивает методы на одном протоколе и воспроизводит эксперимент по версиям данных, кода, настроек и модели. Третий — система сообщает, что данных или качества недостаточно для надёжного объяснения.

## Принятые границы MVP

- Основная метрика — NPV, определённый отдельной спецификацией расчёта. Синтетическая формула служит проверке метода. Модельный NPV на реальных данных должен быть обозначен как модельный.
- Источник входа — локальная таблица кредитов за выбранные периоды, подготовленная по [правилам данных](../data/README.md). Поддержка числовых и категориальных факторов реализована и проверена.
- Сравнение линейных и нелинейных моделей по [протоколу ML](../ml/README.md), анализ основных эффектов, взаимодействий и устойчивости.
- Структурированный результат с происхождением чисел, глобальной важностью, диагностикой форм и чувствительностью вкладов к параметрам.
- LLM выбирает факты и уровень детализации по вопросу; проверенный рендерер формирует текст из каталога расчётов. Числа и предупреждения проверяются до потокового показа. Для OpenRouter ключ хранится локально; аналитика доступна без него.
- Полноценный EC откладывается до определения модели распределения потерь и параметров риска. Промышленное внедрение, торговые решения и автоматическое кредитование в MVP не входят.

## Уточнения и открытые вопросы

1. В заголовке и примере исходного кейса фигурирует EC, а основной сценарий описан через NPV. План начинает с NPV; переход к EC оформляется отдельной спецификацией.
2. В исходном примере изменение равно `15`, а сумма вкладов — `11`. В корректном представлении должен быть остаток `4` либо отдельные подтверждённые эффекты. Исходный кейс не исправляется задним числом.
3. Реальный источник не предоставляет готовую целевую метрику. Исходная стратегия — [ADR 0001](../architecture/decisions/0001-data-and-target-strategy.md); учебная оценка UCI определена в [ADR 0006](../architecture/decisions/0006-uci-model-npv.md).
4. Для UCI зафиксированы месячный горизонт и TWD, для синтетики — условные единицы. Выдачи и погашения не включены: изменение относится только к парной подвыборке.
5. Автоматический выбор факторов не означает использование всех колонок: нужны правила исключения идентификаторов, утечек и недоступных на дату данных.

## Приёмка

| Проверка | Что подтверждает завершение |
| --- | --- |
| Происхождение данных | Источник, версия, преобразования и исключённые строки прослеживаются |
| Целевая метрика | Формула и допущения определены, контрольные примеры проверены |
| Сравнение моделей | Одинаковые разбиения и метрики; есть базовый метод и нелинейные кандидаты |
| Баланс разложения | Сумма непересекающихся эффектов и подписанного остатка воспроизводит изменение в заданном допуске |
| Нелинейности и взаимодействия | Известные эффекты проверены на синтетике; успех не утверждается только по малой ошибке прогноза |
| Глобальная важность | Измеряется отдельно на валидации; её значения не входят в баланс вкладов |
| Устойчивость | Проверены разные периоды, повторные выборки и записанные профили параметров; критерии и отказы документированы |
| Объяснение LLM | Факты имеют ссылки, остаток и предупреждения обязательны; подмена состояния и непроверенный поток отклоняются; реальный провайдер проверяется отдельно от тестовой модели |
| Переносимость | Можно заменить целевую колонку и набор факторов в пределах задокументированного контракта |
| Демонстрация | Сквозной сценарий воспроизводится на синтетике и доступных реальных данных |
| Отчёт по практике | Готовый журнал сохранён по указанию пользователя; текущие файлы перечислены в реестре отчёта |

Численные пороги качества приняты в ADR 0007 до подтверждающего теста. Известные константы устойчивости из архитектурного наброска не считаются обоснованными, пока показатель не определён.

## Уточнение: одна рабочая модель

По указанию пользователя рабочий API и экран всегда используют `stable_gam`,
без автоматического перехода к другой семье. При провале проверок выводится отказ.
Три alpha выбираются на валидации, обязательны 20 повторов и проверка параметров.
[ADR 0010](../architecture/decisions/0010-single-gam.md) и [проверенные результаты](../ml/single-gam.md)
заменяют прежний выбор семьи для каждого рабочего анализа.
